This document says what is built, not how. The user stories are the source of truth: anything not traceable to a story is out of scope.

## Summary

An operations user moves an inspection one step at a time: assign an inspector, start, complete. A step that does not fit the inspection's current status is refused with an error that says why.

## User stories

| ID | Story |
|---|---|
| US-301 | As an operations user, I can assign an inspector to a pending inspection. |
| US-302 | As an operations user, I can start an assigned inspection. |
| US-303 | As an operations user, I can complete an inspection that is in progress. |
| US-304 | As any caller, I get a clear error when I ask for a step that is not allowed, so that I know the inspection's actual status. |

## Workflow

`pending` → `assigned` → `in_progress` → `completed`

| Current status | Action | Next status | Extra rule |
|---|---|---|---|
| `pending` | assign | `assigned` | An inspector name is required, up to 255 characters |
| `assigned` | start | `in_progress` | An inspector must be set |
| `in_progress` | complete | `completed` | |
| `completed` | — | — | No further action |

Every other combination of status and action is invalid.

The time of each step is recorded: when the inspection was assigned, started and completed. A step that has not happened yet has no time.

## Acceptance criteria

API criteria are covered by automated tests. UI criteria are checked by hand.

| ID | Story | Criterion |
|---|---|---|
| AC-301 | US-301 | Assigning a `pending` inspection with an inspector name returns 200, sets status `assigned` and stores the inspector. |
| AC-302 | US-301 | Assigning without an inspector name, or with a blank one, returns 422 and leaves the inspection unchanged. |
| AC-303 | US-302 | Starting an `assigned` inspection returns 200 and sets status `in_progress`. |
| AC-304 | US-303 | Completing an `in_progress` inspection returns 200 and sets status `completed`. |
| AC-305 | US-304 | Any action that does not match the current status returns 409 and leaves the inspection unchanged. This covers skipping a step, going backwards, repeating a step and acting on a completed inspection. |
| AC-306 | US-304 | Starting is refused with 409 if no inspector is set, even when the status is `assigned`. |
| AC-307 | US-304 | Of the 16 possible status pairs, only the 3 in the workflow table are allowed transitions. |
| AC-308 | US-304 | A 409 response is JSON with a `message`, the current status and the action that is allowed next. |
| AC-309 | US-304 | An action on an unknown ID returns 404 as JSON with a `message`. |
| AC-310 | US-301 to US-303 | Each successful step records the time it happened and returns it. Times recorded by earlier steps are not changed, and steps not yet taken have no time. A new inspection has no step times. |
| AC-311 | US-304 | A refused action records no time. |
| UI-301 | US-301 | For a `pending` inspection, the detail panel shows an inspector name input and an "Assign inspector" button. |
| UI-302 | US-302 | For an `assigned` inspection, the detail panel shows a "Start inspection" button. |
| UI-303 | US-303 | For an `in_progress` inspection, the detail panel shows a "Complete inspection" button. A `completed` inspection shows no action. |
| UI-304 | US-301 to US-303 | After an action, the list and the detail panel show the new status. |
| UI-305 | US-304 | If an action is refused or fails, the page shows the error and the inspection's current status. |
| UI-306 | US-301 to US-303 | The detail panel shows the time of each step that has been taken. |

## Out of scope

From the brief: authentication, payments, photo uploads, notifications, deployment.

Not in any story, so not built: cancelling an inspection, moving backwards, reassigning an inspector, and a list of inspectors to choose from.

## Assumptions

| ID | Assumption |
|---|---|
| A-301 | An inspector is identified by a free-text name. The brief allows "name or ID". |
| A-302 | There is no authentication, so any caller may perform any action. |
| A-303 | The workflow only moves forward. `completed` is final. |
| A-304 | The inspector is set once, at assignment. |

## Decisions

This point is not settled by the brief. The author decided it.

| ID | Question | Outcome |
|---|---|---|
| OQ-301 | Should the time of each step (assigned, started, completed) be recorded? | Decided: yes. "Progress" is read as including when each step happened, and these times cannot be filled in later for inspections that have already moved on. See AC-310, AC-311 and UI-306 |
